What is youki?

  • ▸ A low-level OCI container runtime — the thing that actually runs containers
  • ▸ Written in Rust — memory safe, no garbage collector
  • ▸ A drop-in replacement for runc — works with Docker, Podman, containerd
  • ▸ Fully compliant with the OCI Runtime Specification
  • ▸ Name means "container" (容器) in Japanese

// foundations

What is a Container?

// NOT a VM

  • ✗ No separate kernel
  • ✗ No hypervisor overhead
  • ✗ No hardware emulation

// a process with:

  • ▸ Namespaces — isolation
  • ▸ cgroups — resource limits
  • ▸ rootfs — filesystem view
  • ▸ seccomp / caps — syscall filter

// not a new idea

1979 chroot — Unix V7, first filesystem isolation
2000 FreeBSD Jails — network + process isolation
2008 LXC — Linux namespaces + cgroups together
2013 Docker — UX layer that made it mainstream
2015 OCI spec + runc — open standard for runtimes
2019 youki — Rust-native OCI runtime
# containers are just isolated processes
$ ps aux | grep mycontainer
root    12345  nginx -g 'daemon off;'
# same kernel, different "view" of the world

Namespaces — Isolation

🔢
PID
Independent process trees. PID 1 inside the container.
🌐
Network
Own interfaces, routes, firewall rules.
📂
Mount
Separate filesystem tree. pivot_root / chroot.
🏠
UTS
Isolated hostname and domain name.
💬
IPC
Separate shared memory, semaphores, message queues.
👤
User
UID/GID mapping. root-in-container ≠ root-on-host.

syscalls: clone(2), unshare(2), setns(2)

Demo — Namespaces & cgroups

// namespaces
# PID inside vs outside
$ podman run --rm --runtime youki \
  alpine cat /proc/1/status \
  | grep -E "Name|NStgid|Pid"

# hostname is isolated (UTS)
$ podman run --rm --runtime youki \
  alpine hostname

# root inside ≠ root on host (User NS)
$ podman run --rm --runtime youki \
  alpine id
$ id
// cgroups
# run with memory limit
$ podman run --rm --runtime youki \
  --memory 64m alpine \
  cat /sys/fs/cgroup/memory.max

# limit visible CPUs
$ podman run --rm --runtime youki \
  --cpus 0.5 alpine \
  cat /sys/fs/cgroup/cpu.max

# same container, no limit = unlimited
$ podman run --rm --runtime youki \
  alpine cat /sys/fs/cgroup/memory.max
  • ▸ PID 1 inside the container is not PID 1 on the host — that is the namespace
  • ▸ memory.max shows the exact value written to the cgroup on container start
⚠ namespaces and cgroups work exactly the same with youki, runc, or crun — this is Linux kernel behaviour, not the runtime. All OCI-compliant runtimes produce the same result.

// how

How youki Works

Execution flow when you run podman run with youki as runtime

1. Parse Read config.json → validate OCI spec
2. Prepare Create state dir, set up rootfs, spec validation
3. Fork clone(2) with namespace flags → child process
4. Setup mount rootfs, configure cgroups, apply seccomp
5. Exec pivot_root → drop caps → execve(container entrypoint)
6. Track Write PID + state, set up hooks, report back

youki Architecture

$ podman run alpine
▼
crates/youki
CLI · parse args · map to OCI commands
▼
crates/libcontainer
core logic · namespaces · rootfs · seccomp
▼
libcgroups
v1 + v2
oci-spec-rs
config.json
nix
syscalls
▼
Linux Kernel
clone · mount · pivot_root · cgroup files
crates/youki
Entry point. Maps CLI commands (create, start, kill, delete) to libcontainer calls. Talks to Podman via OCI hooks.
crates/libcontainer
The core. Sets up namespaces, mounts rootfs, applies seccomp filters, forks the init process. This is where pivot_root and clone happen.
crates/libcgroups
Writes resource limits to /sys/fs/cgroup/. Supports both v1 and v2. Handles memory, CPU, pids limits.
oci-spec-rs
Parses and validates config.json. Typed Rust structs for the full OCI spec — no manual JSON parsing.
nix
Safe Rust wrappers over Linux syscalls. Replaces raw libc calls with typed, error-handled functions.

Why Rust?

🔒
Memory Safety
Ownership model catches use-after-free, buffer overflows at compile time. No CVEs from memory bugs.
⚡
No GC Pauses
Deterministic memory management. Predictable latency. Critical for a runtime that launches containers.
🧰
C Interop
FFI with libseccomp, libc. Zero-cost abstractions over syscalls via the nix crate.

youki + Podman — Install

# Option 1: build from source (Rust required)
$ git clone https://github.com/containers/youki
$ cd youki
$ cargo build --release --features v2
$ sudo cp target/release/youki /usr/local/bin/

# Option 2: pre-built binary (GitHub releases)
$ wget https://github.com/containers/youki/releases/latest/...
$ chmod +x youki && sudo mv youki /usr/local/bin/

# Verify
$ youki --version
youki 0.3.3
  • ▸ Requires Linux kernel ≥ 5.4 for cgroups v2 support
  • ▸ Optional: libseccomp-dev for seccomp filtering

youki + Podman — Configure

// global config

# /etc/containers/containers.conf
[engine]
  runtime = "youki"

[engine.runtimes]
  youki = [
    "/usr/local/bin/youki"
  ]

// per-run flag

# run with youki explicitly
$ podman run \
  --runtime youki \
  -it alpine sh

# verify which runtime ran
$ podman inspect <ctr> \
  --format "{{.OCIRuntime}}"

Works identically with Docker via daemon.json  |  containerd via config.toml

// security feature

Rootless Containers

  • ▸ Run containers without root — youki maps your UID into user namespace
  • ▸ Uses newuidmap / newgidmap for UID/GID range mapping
  • ▸ cgroups v2 delegation enables resource limits without root
  • ▸ Critically: a privilege escalation in the container ≠ root on host
# full rootless: no sudo anywhere
$ whoami
rodrigo
$ podman run --runtime youki -it alpine sh
# inside container: id → uid=0(root) gid=0(root)
# on host: it's still uid=1000(rodrigo)
# usernamespace mapping: container 0 → host 1000

Pros & Cons

// pros

  • ▸ Memory safe — Rust compiler enforces it at compile time
  • ▸ Faster than runc — 1.8x in startup time (release build)
  • ▸ True drop-in replacement for runc
  • ▸ Active community, good contributor experience
  • ▸ Excellent for learning: clean Rust codebase

// cons

  • ▸ Less battle-tested than runc (in prod since 2015)
  • ▸ Not yet the default in major distros
  • ▸ Build requires Rust toolchain (~few minutes)
  • ▸ Some edge-case OCI features still WIP
  • ▸ Slower than crun — C still has the edge on raw startup speed
  • ▸ RSS memory usage similar to runc — no measurable difference in practice

Runtime Landscape

runc
The reference OCI runtime. Go. Written by Docker. Battle-tested in production. Default everywhere.
crun
C implementation. Fastest and smallest. Default in Fedora/RHEL Podman. Low overhead is the goal.
youki
Rust. Memory safe. Growing community. Perfect for environments where Rust is the standard.
gVisor (runsc)
User-space kernel (Google). Intercepts syscalls. Strong sandbox. Higher overhead. Security-first.
Kata Containers
Lightweight VMs. Full kernel isolation. Slow start (~1s). Needed for multi-tenant environments.
Wasmtime
WebAssembly runtime. Tiny images. Platform-agnostic. Early stage for general workloads.
